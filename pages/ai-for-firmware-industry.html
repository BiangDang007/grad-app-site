AI for 韌體：業界現況調查（2026-10-07）

範圍：「AI 幫人寫／測／驗證／分析韌體」(AI for firmware)。韌體裡跑 AI (TinyML / AI on firmware) 只放最後一節。
方法：本次 session 內 WebSearch + WebFetch（約 45 次）。每項標註來源 URL 與年份。
可信度標記：【已讀】= 本次實際 fetch 到頁面內容；【僅摘要】= 只看到搜尋結果摘要，頁面讀不到或未 fetch，數字請自行再確認；【讀不到】= 403/402/逾時，未繞過。

0. 一句話結論

  • 有，而且 2025-2026 加速：MCU 廠（NXP、TI、Nordic、Espressif、Silicon Labs）都在 IDE 裡接 LLM agent / MCP，讓 agent 能 build、flash、debug、查文件；專門做「AI 寫韌體並在真板子上驗證」的新創（Embedder、BootLoop、H2LooP、CraftifAI）已出現。
  • 瓶頸不在「寫出 C 程式」，而在「對特定晶片的正確性驗證」。學界 benchmark 顯示：不給硬體資訊與回饋，成功率偏低（EmbedBench 最佳約 55-65%）。
  • 學術上最熱的子題是 firmware 安全（fuzzing、漏洞發現、rehosting / 模擬），不是量產韌體生成。
  • 台灣端：只查到聯發科的通用 AI 平台與一則 AI coding agent 職缺（僅摘要），瑞昱、台積電、工研院「AI 生成韌體」的公開動作未查到。
